# Data handling

PR Desk stores numeric GitHub account IDs, account names and creation dates, authored and requested-review PR metadata (including private repository names and PR titles when authorized), review comments, synchronization checkpoints, follow-up states, preferences, notification queue records and browser session identifiers in PostgreSQL. GitHub access tokens are encrypted using the operator-provided key. PR metadata, comment text, follow-up state, queued message bodies and session identifiers are not encrypted by the application. Protect the database and backups accordingly.

Cookies hold a random session identifier, a connection marker and temporary OAuth state. Auth cookies are HttpOnly and Secure when the public origin is HTTPS. Logging in and importing history sends requests to GitHub. Profile avatars load from GitHub. README badges and community charts use external image services, separate from application runtime.

New logins identify the account by GitHub's verified numeric user ID. Separate browser sessions expire after 30 days; they reference a durable account partition and never expose that partition as a browser credential. Reconnecting the same GitHub account reuses its PRs, read/handled state, reminder dates and settings. A matching account name alone never authorizes copying a legacy session's cache: its previous token must also verify the same numeric GitHub ID.

For migrated accounts, Disconnect removes the current browser session, clears its cookies and removes the stored GitHub access token, pausing account synchronization. It preserves the account, PR/comment rows and follow-up settings. Other valid browser sessions can still view the preserved data with a paused-authorization warning. It does not revoke the token at GitHub or remove the GitHub App installation. Legacy sessions still follow their original 30-day access rules and delete their connection record on Disconnect; they migrate on verified login. Neither path automatically purges backups. Users can revoke application access in GitHub settings.

The notification queue is under development in this branch. It contains repository titles, short comment excerpts and direct links so each enabled destination can receive a useful message. The actual gonotify adapter and destination management are not connected yet; do not interpret queued records or passing queue tests as proof that Telegram delivery is active. Connecting this adapter requires finishing the integration checklist in [the follow-up plan](follow-up-plan.md).

The project does not currently implement a complete account deletion/export flow or a published retention period. These are explicit remaining product tasks, not guarantees supplied by open-sourcing the code.
